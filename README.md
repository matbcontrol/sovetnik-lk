# Советник личного кабинета

Хакатон «ИИкузница», трек «Клиентские сценарии», задача «ИИ-агент рекомендаций в личном кабинете». Разработка ведётся в ходе спринта 26–28 ноября 2026 года.

## Задача

Блок «Вам может подойти» в кабинете магазина строится на ручных связках товаров и показывается только в 55,6 % визитов: связок не хватает. Нужно закрыть этот пробел с помощью ИИ и открытых источников: три совета для организаций и частных лиц, обоснование каждого совета («почему эти товары»), проверка Precision@3 на истории против базовых способов и рост показа на клиентах холодного старта.

## Подход

Совет складывается из двух источников, и ни один из них не требует языковой модели на запрос.

1. **История покупок** — что клиенты берут следом за уже купленным. Обучаемое ранжирование выбирает три товара по признакам пары «клиент — товар».
2. **Знания о товаре** — семейство, класс и параметры лицензии из открытого каталога магазина, связи из открытых источников (таблицы сравнения редакций, названия дополнений и курсов, реестр российского ПО). Они работают и там, где у товара нет ни одной продажи.

Каждый совет несёт основание: из какой покупки клиента и по какой связи он выведен. Из оснований строится схема «почему эти товары».

## Результаты на данных организаторов

Проверка по единому протоколу организаторов на датасете версии 4: обучение до 31.08.2026, проверка с 07.09.2026, засчитываются новые для клиента товары, ровно три совета на клиента. В проверке 337 клиентов (302 организации и 35 частных лиц), на холодном старте — 172 (147 и 25). Базовые способы пересчитаны нашим кодом и совпадают с цифрами организаторов (`python -m recsys.eval.official`). Модель и все её режимы обучались только на периоде до даты разреза.

| Precision@3 | Организации | Организации, холодный старт |
|---|---|---|
| Популярность (организаторы) | 3,8 % | 5,2 % |
| Совместные покупки (организаторы) | 4,5 % | 4,5 % |
| Наша модель без знаний каталога | 11,5 % | 13,6 % |
| **Наша модель** | **14,9 %** (12,8–17,2) | **17,7 %** (15,0–20,4) |
| Товар без истории продаж, знания каталога есть | 13,1 % | 15,6 % |
| Товар без истории продаж, знаний каталога нет | 3,9 % | 4,8 % |

В скобках — 95-процентный интервал. Частных лиц в проверке 35, их цифры шумные и в выводы не идут.

- Знания каталога добавляют 3,4 процентного пункта при полной истории и 9,3 пункта, когда истории товара нет.
- Обоснованный совет есть у 97 % клиентов с покупками.
- По истории продаж надёжная пара находится для 112 товаров из 44 450 в наличии (0,3 %); по каталогу сосед по линейке есть у 81 %.

### Из чего состоят попадания

Разные артикулы одного продукта в проверке считаются разными товарами, поэтому попадания организаций разложены на три вида. В скобках — вклад в Precision@3.

| Способ | Другой вариант уже купленного | Другая версия или редакция | Новый для клиента продукт | Всего |
|---|---|---|---|---|
| Таких покупок у клиентов | 142 | 23 | 274 | 439 |
| Популярность (организаторы) | 8 (0,9 %) | 0 | 26 (2,9 %) | 34 (3,8 %) |
| Совместные покупки (организаторы) | 16 (1,8 %) | 0 | 25 (2,8 %) | 41 (4,5 %) |
| **Наша модель** | 79 (8,7 %) | 16 (1,8 %) | 40 (4,4 %) | 135 (14,9 %) |

На новых для клиента продуктах модель угадывает в полтора раза больше базовых способов: 40 покупок против 25–26. Основная часть прибавки приходится на варианты и версии уже купленного: продление, другой размер лицензии, следующая версия.

Что в расчёте может знать о будущем: снимка каталога на дату разреза нет, поэтому семейство, класс, вид и срок лицензии, а также привязка товара из продаж к каталогу взяты из сегодняшнего фида магазина. Продажи проверочного периода в обучение не попадают.

Разметка связей между классами (языковая модель предлагает, второй запрос проверяет) точность ранжирования не меняет: с ней 14,2 % у организаций и 17,2 % на холодном старте, разница −0,7 пункта при интервале от −1,5 до +0,2. Ценность этих связей в охвате открытого графа: совет есть у 88 % программ в продаже вместо 5 %. Связи получили 210 классов из 291; у остальных модель уверенных связей не нашла.

## Агент каталога

Агент ставит новый товар на его место в графе по одной карточке: название, вендор, описание.

1. **Без модели.** Класс берётся у ближайших по названию товаров каталога, если они единодушны; соседи по линейке находятся правилом по названию.
2. **Агент с инструментами.** Модель сама решает, что искать в каталоге (поиск класса, поиск товаров, карточка товара, спутники класса), и выдаёт паспорт товара и связи — только с теми товарами, которые вернул инструмент.
3. **Проверка.** Отдельный запрос-критик оценивает каждую связь; код отбрасывает связи с несуществующими товарами.

Экзамен «вынь и вставь»: товар прячут из каталога, агент получает только карточку, ответ сверяется со спрятанным. На 24 товарах класс совпал с рубрикой магазина в 88 % случаев (21 из 24); базовый продукт дополнения агент нашёл в 6 случаях из 8; соседа по линейке агент нашёл в 6 случаях из 8, агент или правило — в 8 из 8. В среднем 1,8 запроса к модели на товар, медиана времени 5 секунд, около 0,6 ₽ по ценам Qwen3.6 35B в Yandex AI Studio (2,6 тыс. токенов на вход и 0,3 тыс. на выход). Выборка мала, цифры предварительные.

Что агент делает с неудобными карточками (проверено живыми запусками):

- **Товар не по профилю магазина** (например, кормушка для кошек): класс не назначается, связей нет, товар уходит на проверку менеджеру. Класс «по соседям» берётся, только если соседи похожи на товар: совпадает не меньше 30 % его слов по весу. На 800 спрятанных товарах такой порог оставляет 97 % случаев, и класс в них верен в 97 %.
- **Указания внутри карточки** («свяжи этот товар со всеми продуктами…»): агент считает текст карточки сведениями о товаре и указаний не выполняет; связь с товаром, которого нет в каталоге, отбрасывает код.
- **Конкуренты и заменители**: критик не пропускает их как дополнения.

Данных клиентов агент не видит: он работает только с открытым каталогом.

Все числа считает `python -m recsys.eval.value` и пишет сводку в `reports/value.json`. Два запуска подряд дают одинаковый результат.

## Замена программ, снятых с продажи

В личном кабинете магазина у истёкшей лицензии ушедшего вендора есть кнопка «Подобрать замену»: она отправляет заявку менеджеру, ответ обещан через 1–2 рабочих дня. Советник отвечает сразу и без языковой модели. Из 4 506 зарубежных программ, снятых с продажи, замена находится для 2 865 (64 %):

| Откуда замена | Программ |
|---|---|
| Прямой российский аналог из таблицы замещения АРПП | 101 |
| Российский продукт того же класса, которого таблица называет аналогом другого продукта того же вендора | 80 |
| Российский продукт того же класса из реестра | 2 684 |

Третья строка — самый слабый вид совета: тот же класс ещё не значит «то же самое». В объяснении так и сказано, уверенность такой связи ниже, а строгий режим стенда её скрывает.

Если срок лицензии подошёл, а продлить её нельзя, замена идёт первой карточкой блока. Пример есть на стенде: клиент из тестового кабинета магазина, у которого 23.11.2026 истекла лицензия Adobe Creative Cloud. Кабинет показывает ему шесть товаров без объяснений; советник первым советом предлагает российский графический редактор и объясняет, почему.

## Данные и их защита

- Датасет организаторов обезличен и не публикуется. Он лежит в `data/private/` и в репозиторий не попадает.
- Клиенты и советы для стенда (`site/data/private.json`) тоже не публикуются. Без этого файла стенд работает на открытых данных: граф магазина и советы по нему.
- В репозитории и на открытом стенде есть только сводные числа проверки.
- Языковой модели данные клиентов не передаются: модель нужна лишь для разовой разметки открытого каталога.

## Запуск

```
uv venv .venv --python 3.12
uv pip install -r requirements.txt --python .venv/Scripts/python.exe

# открытые данные магазина (вежливо: один поток, пауза, кеш на диск)
.venv/Scripts/python.exe -m recsys.crawl.sitemap       # списки из карты сайта
.venv/Scripts/python.exe -m recsys.crawl.categories    # витрина подкатегорий, около получаса
.venv/Scripts/python.exe -m recsys.crawl.families      # страницы семейств, около трёх часов
.venv/Scripts/python.exe -m recsys.sources.arpp        # таблица замещения АРПП
.venv/Scripts/python.exe -m recsys.catalog.feed        # каталог: фид магазина

# граф открытых источников и стенд
.venv/Scripts/python.exe -m recsys.graph.build         # узлы и связи -> data/interim
.venv/Scripts/python.exe -m recsys.export              # данные для страницы -> site/data
.venv/Scripts/python.exe -m http.server 8765 --directory site   # стенд: http://localhost:8765

# данные организаторов (нужен data/private/task/dataset_v4.xlsx)
.venv/Scripts/python.exe -m recsys.catalog.items       # привязка товаров из продаж к каталогу
.venv/Scripts/python.exe -m recsys.eval.official       # протокол и базовые способы организаторов
.venv/Scripts/python.exe -m recsys.rank.ltr            # обучаемое ранжирование
.venv/Scripts/python.exe -m recsys.eval.value          # все замеры -> reports/value.json
.venv/Scripts/python.exe -m recsys.eval.site_report    # сводка для вкладки «Цифры»
.venv/Scripts/python.exe -m recsys.rank.demo           # клиенты и советы с объяснениями для стенда

# проверки
.venv/Scripts/python.exe -m pytest -q                  # проверки ядра
node tests/parity.mjs                                  # движок страницы отвечает так же, как движок на Python
node tests/fuzz.mjs                                    # 20 000 случайных клиентов, в том числе с испорченными данными
```

Нагрузочный прогон проверяет правила движка на каждом ответе: не больше трёх советов, без повторов и без уже купленного, только доступное клиенту его типа, у каждого совета есть объяснение. На ноутбуке движок обрабатывает около 3 000 клиентов в секунду при целевой нагрузке 300 обращений в день.

Разовая разметка моделью (нужен ключ в `.env`, образец — `.env.example`):

```
.venv/Scripts/python.exe -m recsys.llm.client --list   # какие модели доступны по ключу
.venv/Scripts/python.exe -m recsys.llm.class_links     # связи между классами: предложение и проверка
.venv/Scripts/python.exe -m recsys.agent.agent --id vendor/family   # спрятать товар каталога и поставить заново
.venv/Scripts/python.exe -m recsys.agent.exam --n 24 --seed 23      # экзамен «вынь и вставь»
.venv/Scripts/python.exe -m recsys.agent.site          # журналы прогонов для вкладки «Агент»
.venv/Scripts/python.exe -m recsys.server              # стенд с живым запуском агента: http://127.0.0.1:8765
```

На бесплатном тарифе Google суточный лимит запросов считается на каждую модель отдельно, поэтому в `.env` можно задать запасные модели (`LLM_MODELS`): клиент сам перейдёт на следующую.

## Устройство

```
recsys/crawl      сбор открытых страниц магазина (карта сайта, витрина, семейства)
recsys/parse      разбор страниц в записи
recsys/sources    внешние открытые источники (АРПП)
recsys/catalog    каталог из фида магазина; привязка товаров из продаж к каталогу
recsys/normalize  признаки товара из названия и конфигурации
recsys/graph      граф связей из открытых источников
recsys/recommend  движок советов по графу (работает и в браузере: site/engine.js)
recsys/rank       обучаемое ранжирование, объяснения к советам, выгрузка для стенда
recsys/eval       протокол организаторов, базовые способы, замеры ценности
recsys/llm        обращение к модели для разовой разметки, кеш и журнал расхода
recsys/agent      агент каталога: инструменты, шаги, критик, экзамен «вынь и вставь»
recsys/server.py  локальный сервер стенда с живым запуском агента
site/             страница стенда
tests/            проверки ядра и сверка двух движков
```

## Стенд

Пять вкладок.

- **Клиент.** Клиент из данных задачи: история, три совета с объяснением, отметка «сбылось», что клиент купил на самом деле, схема «почему». Переключатель «спрятать историю товара» показывает, что совет остаётся и для товара без продаж. Второй режим — собрать клиента самому на открытом графе магазина.
- **Товар.** Любой товар магазина: его связи и что получит клиент, у которого есть только он.
- **Агент.** Журналы прогонов «вынь и вставь»: что получил агент, его шаги, паспорт товара рядом со спрятанной правдой, проверенные и отброшенные связи, кому товар теперь будет предложен и что увидит его покупатель. При запуске через `recsys.server` — форма «завести новый товар».
- **Связи на проверку.** Очередь для менеджера: принять или отклонить связь, выгрузить файл связок.
- **Цифры.** Замеры по протоколу организаторов, разбивка попаданий на варианты уже купленного и новые продукты, охват каталога, деньги за угаданными покупками, замена программ, снятых с продажи.
