## 1. Что сделано за 48 часов и что нет

Работает и показано в видео:
- Три совета клиенту — организации или частному лицу — с объяснением простыми словами и схемой «от покупки к совету». Языковая модель при обращении клиента не вызывается.
- Проверка по протоколу организаторов на датасете v4. Precision@3 у организаций 14,9 % (95 % интервал 12,8–17,2) против 3,75 % у популярности и 4,53 % у совместных покупок; на холодном старте 17,7 % против 5,22 % и 4,54 %. Базовые способы пересчитаны нашим кодом и совпали с baseline.py.
- Состав попаданий у организаций: из 135 угаданных покупок 79 — другой вариант уже купленного продукта, 16 — другая версия, 40 — новый для клиента продукт. У базовых способов новых 25–26.
- Товар без истории продаж («соло» или новинка): 13,1 % со знаниями каталога против 3,9 % без них.
- Граф связей из открытых источников на 13 503 товара магазина: редакции и версии, дополнения и курсы, российские аналоги, связи между классами.
- Замена зарубежных программ, снятых с продажи: находится сразу для 2 865 из 4 506. В кабинете такая заявка уходит менеджеру на 1–2 рабочих дня.
- Агент каталога ставит новый товар в граф по одной карточке. Экзамен на 24 спрятанных товарах: класс совпал с рубрикой магазина в 88 %, в среднем 1,8 вызова модели и 5 секунд на товар.
- Стенд из пяти вкладок: клиент, товар, агент, связи на проверку, цифры.

Сделано частично:
- Связи между классами размечены для 210 классов из 291. Точность ранжирования они не повышают (−0,7 пункта, в пределах погрешности), их польза — охват открытого графа.
- Замена «тот же класс из реестра» (2 684 программы из 2 865) — слабый вид совета, его должен подтверждать менеджер.
- Экзамен агента проведён на 24 товарах: выборка мала.
- Частных лиц в проверке 35, их цифры шумные.
- На открытом стенде показаны записи прогонов агента; живой запуск работает на локальном стенде, где есть ключ модели.

Не сделано: встраивание в кабинет, учёт показов и переходов, прогон на модели, размещённой в России (стоимость посчитана по её ценам).

## 2. Подход и архитектура

Путь запроса клиента. История покупок клиента → кандидаты → три совета → объяснение. Советы дают два источника:
1. Обученное ранжирование (градиентный бустинг, 42 признака пары «клиент — товар»): что брали следом за тем же товаром, семейством и классом, подошёл ли срок лицензии, как соотносятся вид лицензии, размер и срок. Учится на копиях протокола, сдвинутых в прошлое; проверочный период в обучение не попадает.
2. Движок по графу открытого каталога: продление, следующая редакция или версия, дополнение, замена. Запреты: нет в продаже, уже куплено, не тот тип клиента, та же линейка.

Объяснение собирается из тех же оснований, по которым совет выбран, без модели. Ответ считается за доли миллисекунды; на стенде расчёт идёт в браузере.

Источники данных: обезличенные продажи организаторов, фид магазина (135 890 предложений), открытые страницы магазина (семейства, таблицы сравнения редакций, витрина), таблица замещения АРПП.

Где решения принимает модель:
- Разовая разметка связей между классами каталога: один запрос предлагает связи, второй, в роли придирчивого закупщика, отсеивает слабые.
- Агент каталога для нового товара. Сначала правила без модели: класс по похожим товарам, соседи по линейке по названию. Затем модель с инструментами (поиск класса, поиск по каталогу, карточка товара, спутники класса) собирает паспорт товара и связи. Затем второй запрос проверяет каждую связь.

Как проверяется ответ:
- Код отбрасывает связи с товарами, которых нет в каталоге. Класс «по соседям» берётся, только если соседи похожи на товар не меньше чем на 30 % слов по весу.
- Товар не по профилю магазина остаётся без класса и связей и уходит менеджеру. Текст карточки считается сведениями о товаре, а не указаниями модели.
- Экзамен «вынь и вставь»: товар прячем из каталога, ответ агента сверяем со спрятанным.
- Менеджер принимает или отклоняет связи в очереди на стенде; отклонённая связь сразу выпадает из советов.
- Ранжирование проверяется протоколом организаторов; два запуска подряд дают одинаковые числа. Движок страницы сверен с движком на Python на 300 клиентах, нагрузочный прогон на 20 000 случайных клиентов нарушений не нашёл.

## 3. Стек и модели

- Python 3.12: scikit-learn, pandas, numpy, requests, BeautifulSoup, lxml, openpyxl, pytest.
- Стенд: HTML, CSS и JavaScript без сторонних библиотек; движок советов работает в браузере. Локальный сервер на стандартной библиотеке Python нужен только для живого запуска агента.
- Модели: Google Gemini 3.5 Flash-Lite и 3.1 Flash-Lite через Google AI Studio — разметка классов и агент. Модель подключается через адаптер и меняется настройкой, в том числе на OpenAI-совместимый адрес. Стоимость посчитана по ценам Qwen3.6 35B в Yandex AI Studio. Модель получает только открытый каталог, данных клиентов не получает.
- Баз данных нет: граф и справочники — файлы JSON и CSV, в памяти около 4 МБ.
- Хостинг: статическая страница. Для агента и переобучения хватает одной небольшой виртуальной машины без видеокарты.

## 5. Запуск и поставка

Состав: recsys/ — код, site/ — стенд, tests/ — проверки, reports/ — сводные числа, README.md — команды, submission/ — расчёт стоимости и материалы сдачи. Среда: Windows или Linux, Python 3.12, 8 ГБ памяти.

Запуск стенда:
uv venv .venv --python 3.12
uv pip install -r requirements.txt --python .venv/Scripts/python.exe
.venv/Scripts/python.exe -m recsys.server
Стенд откроется на http://127.0.0.1:8765. Проверка на данных организаторов: положить dataset_v4.xlsx в data/private/task/, затем python -m recsys.eval.official (базовые способы) и python -m recsys.eval.value (все замеры, около 5 минут).

Пример запроса: организация; покупки — Kaspersky Endpoint Security Стандартный (11.05.2026, 12 мес.), Adobe Creative Cloud (23.11.2025, 12 мес.), Dr.Web Desktop Security Suite, Microsoft 365 Personal; дата 26.11.2026.

Ожидаемый ответ — три совета:
1. Замена: AliveColors. «Лицензия Adobe Creative Cloud: куплена 23.11.2025, на 12 мес., истекла 23.11.2026. Продлить её в магазине нельзя. Российский продукт того же класса из реестра — AliveColors; в таблице замещения он назван аналогом Adobe Photoshop».
2. Чего не хватает: Кибер Бэкап — резервное копирование к антивирусу.
3. Следующая ступень: Kaspersky Endpoint Security Расширенный — добавляет шифрование данных и контроль запуска приложений.

На стенде это первый пример на вкладке «Клиент». Логин не нужен. Клиенты из датасета на открытом стенде не показаны, потому что данные нельзя публиковать: они есть в видео и на питче, в локальном запуске того же стенда.
