# Описание продукта для формы сдачи

Тексты по пунктам 4.5(2) Положения. Продукт: «Советник личного кабинета».

## Реализовано за время спринта

- **Три совета клиенту** — организациям и частным лицам — по истории покупок и каталогу. Проверка по протоколу организаторов: Precision@3 для организаций 13,9 % (интервал 12,0–15,9) против 3,6–3,9 % у базовых способов; на холодном старте 16,0 % против 3,8–5,1 %.
- **Обоснование каждого совета** простыми словами и с числами, без языковой модели, и схема «почему эти товары»: от конкретной покупки клиента к совету.
- **Ответ на «соло»-товары и новинки.** Если у товара нет истории продаж, знания каталога (линейка, класс, параметры лицензии) дают 13,0 % против 3,5 % без них.
- **Граф связей из открытых источников** на 13,5 тыс. товаров магазина: редакции и версии, дополнения и курсы, российские аналоги из реестра, связи между классами. Совет есть у 88 % программ в продаже.
- **Агент каталога.** Ставит новый товар в граф по одной карточке: класс, назначение, что нужно для работы, связи с товарами каталога. Каждую связь проверяет второй запрос. Экзамен «вынь и вставь» на 24 спрятанных товарах: класс совпал с рубрикой магазина в 88 % случаев, 1,8 запроса к модели и около 0,6 ₽ на товар. Товар не по профилю магазина агент не привязывает, а отправляет на проверку; указания, вписанные в карточку товара, не выполняет.
- **Стенд** из пяти вкладок: клиент, товар, агент, связи на проверку, цифры.
- **Очередь связей для менеджера** и выгрузка файла связок в том же виде, в каком блок работает сейчас.
- **Замеры ценности**: показ, попадание, вклад знаний каталога, охват каталога, деньги за угаданными покупками.
- **Проверки**: 12 проверок ядра, сверка движка страницы с движком на Python на 300 клиентах, нагрузочный прогон на 20 000 случайных клиентов (около 3 000 клиентов в секунду, нарушений правил нет).

## Не реализовано

- Встраивание в личный кабинет и учёт показов, переходов и покупок: по условиям задачи интеграции не предусмотрены.
- Связи между классами получили 210 классов из 291; у остальных модель уверенных связей не нашла.
- Экзамен агента проведён на 24 товарах — выборка мала, цифры предварительные.
- Прогон на модели, доступной в России: расчёт стоимости сделан по её ценам, сама разметка шла на Google Gemini.
- Живой запуск агента на открытом стенде: он требует сервера с ключом модели; на стенде показаны записи настоящих прогонов.

## Подход и архитектура

Совет складывается из двух источников, и ни один не требует языковой модели в момент обращения клиента.

1. **История покупок.** Обучаемое ранжирование (градиентный бустинг) выбирает три товара по признакам пары «клиент — товар»: что брали следом за тем же товаром, семейством и классом, подошёл ли срок, как соотносятся вид лицензии, число мест и срок. Модель учится на копиях протокола, сдвинутых в прошлое; проверочный период в обучении не участвует.
2. **Знания о товаре.** Каталог из фида магазина (семейство, класс, параметры лицензии) и граф связей из открытых источников. Они работают и там, где у товара нет продаж.

Языковая модель используется только заранее: размечает связи между классами каталога и работает в агенте, который ставит новый товар в граф. Агент устроен в три ступени: правила без модели, шаги с инструментами (поиск класса, поиск по каталогу, карточка товара, спутники класса), проверка связей вторым запросом. Данных клиентов модель не получает.

Объяснение совета собирается из тех же сведений, по которым совет выбран; путь от покупки клиента к совету рисуется на схеме.

## Стек и модели

- Python 3.12: pandas, numpy, scikit-learn, requests, BeautifulSoup, lxml, openpyxl.
- Страница стенда — HTML, CSS и JavaScript без сторонних библиотек; движок советов по графу работает в браузере.
- Языковые модели для разметки и агента: Google Gemini (gemini-3.6-flash, gemini-3.5-flash-lite, gemini-3.1-flash-lite) через Google AI Studio. Адаптер совместим с OpenAI API; расчёт стоимости сделан для Qwen3.6 35B в Yandex AI Studio.

## Запуск и состав поставки

Состав: исходный код (`recsys/`), страница стенда (`site/`), проверки (`tests/`), сводные отчёты (`reports/`), описание и команды запуска (`README.md`), расчёт стоимости и тексты для формы (`submission/`).

Запуск стенда на открытых данных:

```
uv venv .venv --python 3.12
uv pip install -r requirements.txt --python .venv/Scripts/python.exe
.venv/Scripts/python.exe -m recsys.server
```

Проверка на данных организаторов (датасет кладётся в `data/private/task/dataset_v3.xlsx`): команды перечислены в `README.md`, итоговые цифры считает `python -m recsys.eval.value`.

Датасет организаторов и строки клиентов в репозитории и на открытом стенде не публикуются.
