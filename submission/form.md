В личные советы идёт «нужно» с фразой «зачем» и не больше одного «комплекта» последней карточкой. ## 2. Подход и архитектура

Путь запроса клиента: история покупок → кандидаты → проверка пар → блок → объяснение. Три источника:
1. Обученное ранжирование (градиентный бустинг, 42 признака пары «клиент — товар»): что брали следом за тем же товаром, семейством и классом, подошёл ли срок лицензии. Учится на копиях протокола, сдвинутых в прошлое; проверочный период в обучение не попадает.
2. Движок по графу открытого каталога: продление, следующая редакция или версия, дополнение, замена. Запреты закрывают типичные ошибки: не тот тип клиента или платформа, дубль купленного (уже куплено, та же линейка, «то же самое»), снято с продажи, в разы дороже купленного.
3. Таблицы вердиктов пар. Чужой продукт попадает в личные советы с вердиктом «нужно»; «комплект» — не больше одного, последней карточкой. На открытом каталоге — если проверена пара с товаром клиента или товар для всего его класса; неподтверждённый подбор по связи классов — подсказка менеджеру, на стенде — отдельной строкой «Совместимость требует проверки».

Объяснение собирается из тех же оснований, по которым совет выбран, без модели. Ответ — в среднем меньше миллисекунды, около 1 400 клиентов в секунду.

Источники данных: обезличенные продажи организаторов, фид магазина от 26.11.2026, открытые страницы магазина, таблица замещения АРПП.

Где решения принимает модель:
- Разметка пар по правилам менеджера: первая — ИИ-ассистентом, новые пары — двумя моделями по API; их согласие «не советовать» действует сразу, остальное решает менеджер.
- Агент каталога для нового товара: паспорт, класс и связи среди кандидатов кода (при нехватке сама вызывает поиск), проверка связей критиком; результат — предложение менеджеру.

Как проверяется ответ:
- Вердикты сверены с покупками обучающего периода: если стоит «уже есть», а товар заметно часто берут следом, вердикт исправлен; утечку проверочного периода в этой сверке нашло ревью, она исправлена. Отклонённая менеджером связь сразу выпадает из советов.
- Связь агента идёт клиенту, только если критик привёл дословную цитату, код нашёл её в тексте и это не название товара; остальное — менеджеру. Несуществующие товары и указания внутри карточки код отбрасывает.
- Два запуска ранжирования дают одинаковые числа; движок страницы сверен с Python на 300 клиентах.

## 3. Стек и модели

- Python 3.12: scikit-learn, pandas, numpy, requests, BeautifulSoup, lxml, openpyxl, pytest.
- Стенд: HTML, CSS и JavaScript без библиотек, движок работает в браузере; сервер на Python нужен только для живого запуска агента.
- Модели: Gemini 3.5 Flash-Lite, 3.1 Flash-Lite и 3.6 Flash (Google AI Studio), deepseek-v4-pro (DeepSeek API) — агенты и разметка пар. Первая разметка пар — Claude, ИИ-ассистент разработки. Модель меняется настройкой, для России — Yandex AI Studio. Стоимость по замерам и тарифам этих моделей: около 0,45 ₽ на обращение вместе с сервером; главная статья — время менеджера, около 55 минут в день при 10 новых товарах. По API уходили только названия и описания из открытого каталога; данных клиентов модель не получает.
- Баз данных нет: граф и таблицы вердиктов — файлы JSON и CSV.
- Хостинг: статическая страница. Пересчёт ранжирования раз в сутки занимает около 2 минут процессора; для него и для агента хватает небольшой ВМ без видеокарты.

## 5. Запуск и поставка

Среда: Python 3.12, 8 ГБ памяти; команды ниже — для Windows, на Linux путь к Python — .venv/bin/python. Открытые данные магазина лежат в репозитории, обход не нужен.

Запуск стенда:
uv venv .venv --python 3.12
uv pip install -r requirements.txt --python .venv/Scripts/python.exe
.venv/Scripts/python.exe -m recsys.server
Стенд откроется на http://127.0.0.1:8765. Проверка на данных организаторов: положить dataset_v5.xlsx в data/private/task/, затем python -m recsys.eval.official (базовые способы), python -m recsys.eval.value (все замеры, около 5 минут) и python -m recsys.eval.robust (устойчивость).

Пример запроса: организация; покупки — Kaspersky Endpoint Security Стандартный (11.05.2026, 12 мес.), Adobe Creative Cloud (23.11.2025, 12 мес.), Dr.Web Desktop Security Suite (11.05.2026), Microsoft 365 Personal (30.04.2026); дата 26.11.2026.

Ожидаемый ответ клиенту: 1) следующая ступень — Kaspersky Endpoint Security Расширенный; 2) к вашему продукту — Kaspersky EDR Оптимальный; 3) типовой набор — Traffic Inspector («если ещё нет шлюза…»). Отдельной строкой «Часто докупают» — КриптоПро CSP; под блоком — ещё 2 совета ждут менеджера.

На стенде это первый пример на вкладке «Клиент». Клиенты из датасета есть только в локальном запуске и в видео: данные нельзя публиковать.
