## 2. Подход и архитектура

Путь запроса клиента: история покупок → кандидаты → проверка пар → блок → объяснение. Три источника:
1. Обученное ранжирование (градиентный бустинг, 42 признака пары «клиент — товар»): что брали следом за тем же товаром, семейством и классом, подошёл ли срок лицензии. Учится на копиях протокола, сдвинутых в прошлое; проверочный период в обучение не попадает.
2. Движок по графу открытого каталога: продление, следующая редакция или версия, дополнение, замена. Запреты закрывают типичные ошибки: не тот тип клиента или платформа, дубль купленного (уже куплено, та же линейка, «то же самое»), снято с продажи, в разы дороже купленного.
3. Таблицы вердиктов пар. Чужой продукт попадает в личные советы с вердиктом «нужно»; «комплект» — не больше одного, последней карточкой. На открытом каталоге — если проверена пара с товаром клиента или товар для всего его класса; подбор по связи классов — подсказка менеджеру.

Объяснение собирается из тех же оснований, по которым совет выбран, без модели. Ответ считается за доли миллисекунды; на стенде расчёт идёт в браузере.

Источники данных: обезличенные продажи организаторов, фид магазина от 26.11.2026 (135 890 предложений), открытые страницы магазина (семейства, таблицы сравнения редакций, витрина), таблица замещения АРПП.

Где решения принимает модель:
- Разметка пар по правилам менеджера. Первая — ИИ-ассистентом при разработке, новые пары — моделью по API тем же запросом. Сверка с первой разметкой решает, идут ли вердикты модели клиенту без менеджера.
- Агент каталога для нового товара. Код находит похожие товары и кандидатов в связи; модель выбирает класс и связи, при необходимости сама вызывает инструменты поиска; второй запрос проверяет каждую связь. Результат — предложение менеджеру.

Как проверяется ответ:
- Вердикты сверены с покупками: если стоит «уже есть», а товар заметно часто берут следом, вердикт исправлен (так «КриптоАРМ → КриптоПро CSP» стало «нужно»). Отклонённая менеджером связь сразу выпадает из советов.
- Код отбрасывает связи с товарами, которых нет в каталоге. Товар не по профилю магазина остаётся без класса и уходит менеджеру. Текст карточки считается сведениями о товаре, а не указаниями модели.
- Экзамен «вынь и вставь»: товар прячем из каталога, ответ агента сверяем со спрятанным и с тем, что дал бы один код.
- Ранжирование проверяется протоколом организаторов; два запуска подряд дают одинаковые числа. Движок страницы сверен с движком на Python на 300 клиентах, нагрузочный прогон на 20 000 случайных клиентов нарушений не нашёл.

## 3. Стек и модели

- Python 3.12: scikit-learn, pandas, numpy, requests, BeautifulSoup, lxml, openpyxl, pytest.
- Стенд: HTML, CSS и JavaScript без сторонних библиотек; движок советов работает в браузере. Сервер на стандартной библиотеке Python нужен только для живого запуска агента.
- Модели через Google AI Studio: Gemini 3.5 Flash-Lite и 3.1 Flash-Lite — агент каталога и сверка разметки пар. Первая разметка пар — Claude, ИИ-ассистент разработки. Модель меняется настройкой, в том числе на OpenAI-совместимый адрес. Стоимость посчитана по ценам Qwen3.6 35B в Yandex AI Studio. Модель по API получает только открытый каталог, данных клиентов не получает.
- Баз данных нет: граф, справочники и таблицы вердиктов — файлы JSON и CSV, в памяти около 5 МБ.
- Хостинг: статическая страница. Пересчёт ранжирования раз в сутки занимает около 2 минут процессора; для него и для агента хватает небольшой ВМ без видеокарты.

## 5. Запуск и поставка

Состав: recsys/ — код, knowledge/ — вердикты, site/ — стенд, tests/, reports/ — сводные числа, submission/ — материалы сдачи. Среда: Python 3.12, 8 ГБ памяти; команды ниже — для Windows, на Linux путь к Python — .venv/bin/python. Открытые данные магазина лежат в репозитории, обход не нужен.

Запуск стенда:
uv venv .venv --python 3.12
uv pip install -r requirements.txt --python .venv/Scripts/python.exe
.venv/Scripts/python.exe -m recsys.server
Стенд откроется на http://127.0.0.1:8765. Проверка на данных организаторов: положить dataset_v4.xlsx в data/private/task/, затем python -m recsys.eval.official (базовые способы), python -m recsys.eval.value (все замеры, около 5 минут) и python -m recsys.eval.robust (устойчивость).

Пример запроса: организация; покупки — Kaspersky Endpoint Security Стандартный (11.05.2026, 12 мес.), Adobe Creative Cloud (23.11.2025, 12 мес.), Dr.Web Desktop Security Suite (11.05.2026), Microsoft 365 Personal (30.04.2026); дата 26.11.2026.

Ожидаемый ответ клиенту: 1) следующая ступень — Kaspersky Endpoint Security Расширенный; 2) к вашему продукту — Kaspersky EDR Оптимальный; 3) типовой набор — Traffic Inspector («если ещё нет шлюза…»). Отдельной строкой «Часто докупают» — КриптоПро CSP с подписью «не личный совет»; под блоком — ещё 2 совета ждут менеджера. Когда менеджер принимает замену для класса «Графические редакторы», первым советом становится AliveColors: лицензия Adobe истекла, полной замены в таблице замещения нет.

На стенде это первый пример на вкладке «Клиент». Клиенты из датасета есть только в локальном запуске и в видео: данные нельзя публиковать.
