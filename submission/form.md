## 1. Что сделано за 48 часов и что нет

Работает и показано в видео:
- Три совета клиенту — организации или частному лицу — с объяснением и схемой «от покупки к совету». Языковая модель при обращении клиента не вызывается.
- Проверка по протоколу организаторов на датасете v4; базовые способы пересчитаны нашим кодом и совпали с baseline.py. Precision@3, группа A / группа B: организации 14,9 % / 17,7 % против 3,75–4,53 % / 4,54–5,22 % у базовых способов; частные лица 21,9 % / 24,0 % против 15,2–20,0 % / 14,7–20,0 % — у частных лиц прибавка в пределах погрешности. Fill Rate модели 100 % в обеих группах, у совместных покупок 92,3 % и 87,2 %. Совет по собственному основанию, а не «часто берут», есть у 99,4 % и 98,8 % клиентов.
- Устойчивость: на пяти зёрнах у организаций 14,6–15,0 %; без знаний каталога и профиля клиента (они взяты из сегодняшних данных и могут знать будущее) — 10,6 %; на двух более ранних разрезах — 13,7–13,8 % против 4,3–5,1 % у базовых способов.
- Из чего прибавка: из 135 угаданных покупок организаций 95 — другой артикул или версия уже купленного продукта. Среди остальных 40 ручная проверка нашла ещё не меньше 15 вариантов купленного и 19 случаев КриптоПро CSP. Модель сильна в следующем шаге по купленному: продление, размер, редакция. На действительно новых продуктах она примерно на уровне популярности. Наш сильный базовый способ без обучения — правило «та же линейка» — даёт 10,9 %, модель выше на 4,0 пункта.
- Граф связей из открытых источников на 13 503 товара: редакции и версии, дополнения и курсы, российские аналоги, связи между классами. Если у купленного товара спрятать историю пар (так моделируется новинка), знания каталога держат 13,1 % против 3,9 % без них.
- Очередь менеджера: 452 строки (связи между классами и замены по классу) вместо примерно 6 000 ручных связок. Непроверенную связь по классу клиент не видит. Из 17 связей классов, которые можно проверить продажами, подтвердились 13.
- Замена зарубежных программ, снятых с продажи, подготовлена для 2 865 из 4 506: прямой аналог (101) клиент видит сразу, замену по классу — после решения менеджера. В кабинете такая заявка уходит менеджеру на 1–2 рабочих дня.
- Агент каталога: по карточке нового товара код находит кандидатов, модель выбирает класс и связи, второй запрос их проверяет. Экзамен на 24 спрятанных товарах: класс верен в 21 случае из 24, один код без модели — 20 из 24, модель без подсказок кода — 8 из 24. 1,8 вызова модели и 0,49 ₽ на товар.
- Стенд из пяти вкладок: клиент, товар, агент, связи на проверку, цифры.

Сделано частично:
- Правила показа в режиме кабинета (продление только в срок, массовый товар не всем, домашние лицензии не организациям) — ПРОВЕРИТЬ ПЕРЕД СДАЧЕЙ.
- Связи между классами размечены для 210 классов из 291 и точность ранжирования не повышают; их польза — охват открытого графа.
- Решения менеджера хранятся в браузере стенда, серверного хранения нет.
- Экзамен агента — 24 товара, все 8 дополнений одного вендора; выборка мала.
- Симуляция пользователей: восемь ролей получили настоящие ответы блока, по её итогам переписаны объяснения и введено правило про непроверенные связи. Настоящих пользователей она не заменяет.
- Живой запуск агента — на локальном стенде с ключом модели; на открытом стенде — записи прогонов.

Не сделано: встраивание в кабинет; учёт показов и переходов (ссылки уже несут метки перехода, как у блока кабинета); прогон на модели, размещённой в России (стоимость посчитана по её ценам).

## 2. Подход и архитектура

Путь запроса клиента: история покупок клиента → кандидаты → три совета → объяснение. Советы дают два источника:
1. Обученное ранжирование (градиентный бустинг, 42 признака пары «клиент — товар»): что брали следом за тем же товаром, семейством и классом, подошёл ли срок лицензии, как соотносятся вид лицензии, размер и срок. Учится на копиях протокола, сдвинутых в прошлое; проверочный период в обучение не попадает.
2. Движок по графу открытого каталога: продление, следующая редакция или версия, дополнение, замена. Запреты: нет в продаже, уже куплено, не тот тип клиента, та же линейка.

Объяснение собирается из тех же оснований, по которым совет выбран, без модели. Ответ считается за доли миллисекунды; на стенде расчёт идёт в браузере.

Источники данных: обезличенные продажи организаторов, фид магазина (135 890 предложений), открытые страницы магазина (семейства, таблицы сравнения редакций, витрина), таблица замещения АРПП.

Где решения принимает модель:
- Разовая разметка связей между классами каталога: один запрос предлагает связи, второй, в роли придирчивого закупщика, отсеивает слабые.
- Агент каталога для нового товара. Код без модели находит похожие товары и кандидатов в связи. Модель выбирает класс и связи и при необходимости сама вызывает инструменты: поиск класса, поиск по каталогу, карточку товара, спутников класса. Второй запрос проверяет каждую связь. Результат — предложение менеджеру.

Как проверяется ответ:
- Код отбрасывает связи с товарами, которых нет в каталоге. Класс «по соседям» берётся, только если соседи похожи на товар не меньше чем на 30 % слов по весу и единодушны.
- Товар не по профилю магазина остаётся без класса и связей и уходит менеджеру. Текст карточки считается сведениями о товаре, а не указаниями модели.
- Связь по классу клиент видит, только если её подтвердили продажи (не меньше трёх клиентов) или принял менеджер. Отклонённая связь сразу выпадает из советов.
- Экзамен «вынь и вставь»: товар прячем из каталога, ответ агента сверяем со спрятанным и с тем, что дал бы один код.
- Ранжирование проверяется протоколом организаторов; два запуска подряд дают одинаковые числа. Движок страницы сверен с движком на Python на 300 клиентах, нагрузочный прогон на 20 000 случайных клиентов нарушений не нашёл.

## 3. Стек и модели

- Python 3.12: scikit-learn, pandas, numpy, requests, BeautifulSoup, lxml, openpyxl, pytest.
- Стенд: HTML, CSS и JavaScript без сторонних библиотек; движок советов работает в браузере. Локальный сервер на стандартной библиотеке Python нужен только для живого запуска агента.
- Модели через Google AI Studio: Gemini 3.5 Flash-Lite и 3.1 Flash-Lite — агент каталога; gemini-3.6-flash и Flash-Lite — разметка связей между классами. Модель подключается через адаптер и меняется настройкой, в том числе на OpenAI-совместимый адрес. Стоимость посчитана по ценам Qwen3.6 35B в Yandex AI Studio. Модель получает только открытый каталог, данных клиентов не получает.
- Баз данных нет: граф и справочники — файлы JSON и CSV, в памяти около 4 МБ.
- Хостинг: статическая страница. Пересчёт ранжирования раз в сутки занимает около 2 минут процессора; для него и для агента хватает небольшой ВМ без видеокарты.

## 5. Запуск и поставка

Состав: recsys/ — код, site/ — стенд, tests/ — проверки, reports/ — сводные числа, README.md — команды, submission/ — расчёт стоимости и материалы сдачи. Среда: Python 3.12, 8 ГБ памяти; команды ниже — для Windows, на Linux путь к Python — .venv/bin/python. Открытые данные магазина лежат в репозитории, обход не нужен.

Запуск стенда:
uv venv .venv --python 3.12
uv pip install -r requirements.txt --python .venv/Scripts/python.exe
.venv/Scripts/python.exe -m recsys.server
Стенд откроется на http://127.0.0.1:8765. Проверка на данных организаторов: положить dataset_v4.xlsx в data/private/task/, затем python -m recsys.eval.official (базовые способы) и python -m recsys.eval.value (все замеры, около 5 минут) и python -m recsys.eval.robust (устойчивость).

Пример запроса: организация; покупки — Kaspersky Endpoint Security Стандартный (11.05.2026, 12 мес.), Adobe Creative Cloud (23.11.2025, 12 мес.), Dr.Web Desktop Security Suite, Microsoft 365 Personal; дата 26.11.2026.

Ожидаемый ответ клиенту — три совета:
1. Чего не хватает: Кибер Бэкап — резервное копирование к антивирусу; связь классов подтверждена покупками.
2. Следующая ступень: Kaspersky Endpoint Security Расширенный — добавляет шифрование данных и контроль запуска приложений.
3. Следующая ступень: Kaspersky Total Security.
Под блоком написано, что ещё 4 связи по классу ждут проверки менеджера. Когда менеджер принимает в очереди замену для класса «Графические редакторы», первым советом становится AliveColors: «Лицензия Adobe Creative Cloud истекла 23.11.2026. Полной замены в таблице замещения нет. Ближайший российский продукт того же класса — AliveColors; в таблице он назван аналогом Adobe Photoshop».

На стенде это первый пример на вкладке «Клиент». Логин не нужен. Клиенты из датасета на открытом стенде не показаны, потому что данные нельзя публиковать: они есть в видео и на питче, в локальном запуске того же стенда.
